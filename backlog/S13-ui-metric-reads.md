# S13 — UI: fewer metric reads per view

**Type:** build (frontend only)
**Depends on:** none for the code; human GUI measurement for acceptance
**Source:** `source/PERF.md` (layer 3, options 1 and 2)

## Goal
Cut the number of backend calls per view: History reads a series in one call,
and `getMetricStates` is coalesced per scope.

## Background
Each `metric()` read in a component makes an uncached `getMetricStates` call
(about 48 ms each). A cold Match Overview spends about 0.6 s on backend calls;
a 100-row History about 25 s. `getMetricSeries` exists and is unused by the UI.

## Work
- `HistoryPanel` uses `getMetricSeries`, with one state read per panel.
- Coalesce state reads per (scope, id) in `componentruntime/readapi.js`, with a
  short-lived dedupe and no TTL.
- Do not add a cache with a TTL here. Stale-state bugs are the risk.

## Acceptance
- Call counts per view reduced (measured with the harness in `scratchpad`).
- **Human GUI measurement** (AGENTS.md: agents do not drive the GUI): time cold
  and warm Overview, Scoreboard, and History at 100 rows.

## Not covered
Wails bridge overhead and render time are unmeasured. The 25 s History figure
is an extrapolation.

## Result

**What changed** (`src/frontend/src/lib/`):
- `componentruntime/readapi.js`: in-flight dedupe (`sharedRead`) keyed by method
  and arguments, held per reads object. Concurrent identical reads share one
  promise; the entry is removed when the read settles, success or failure. No
  TTL, and a rejected read is not replayed. `metric()` reads its compute states
  through it (per scope and id).
- `componentruntime/readapi.js`: new exported `metricsByMatch(reads, steamId,
  names, matchIds)`. One `getMetricSeries` read for the player's metric set, plus
  one `getMetricStates('match', id)` per match (that call carries every metric).
  Cells get the same five-state word from `metricPresentation`. An empty metric
  set or match set never reaches the backend (an empty id list reads every
  metric). It is deliberately not on the `spectra` surface, whose method set is
  pinned by a test and visible to user components.
- `componentruntime/reads.js`: `metricsByMatch(steamId, names, matchIds)` bound to
  the real services. It is listed in `BUILTIN_HELPERS` (`compile.js`) so the
  History panel may import it. **That allowlist entry is a review item.**
- `builtins/profile/HistoryPanel.svelte`: one `metricsByMatch` call replaces the
  per-cell `spectra.metric()` loop. The `failedRead` import is gone.
- `componentreadapi.test.js`: 9 new tests (dedupe, no TTL, rejected reads,
  `metricsByMatch` calls, states, empty sets, unknown names).

**Known difference from `metric()`:** for a match-grain read, "has rows" is this
player's row, or the match state being fresh. `metric()` counts all players'
rows in the match. The two differ only when a match is `behind` yet holds fresh
rows for other players. Here that cell shows the behind chip, and `metric()`
would show a dash.

**Tests:** `node --test src/lib/*.test.js` gives 988 pass, 0 fail (with the Wails
bindings generated by `wails3 generate bindings`). Without bindings, `download`
and `input` fail on a missing `bindings/` module, as they did before this change.
`npx vite build` exits 0.

**Still open:** the states are one read per row. A batched per-match state read
on the Go side would take that to one call. That is a backend change and is not
in this story.

**Human GUI measurement (owed, not done by an agent):** time cold and warm
Overview, Scoreboard, and History at 100 rows, before and after this change.
