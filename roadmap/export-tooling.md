# CLI, shortcuts & parse cache — roadmap research

**Unit:** export-tooling · **Priority tier:** P1 · **Date:** 2026-11-10
**LoE (aggregate):** M — one M (scoped CLI v1 over services that already exist headless) plus two S items (a shortcut reference registry, and a reprocess fast-path + one library sort key) ≈ 3–5 sequential days; unscoped "all GUI parity" CLI would be L+ and is explicitly out of scope.
**Feasibility:** high — all three items reuse proven scaffolding (`runImport` proves headless composition, `KBD_HINTS`/`input.js` prove the shortcut inventory, `sha256`+`parser_version` columns already exist); blockers are policy/design, not plumbing: item 2's single-writer DB safety when a CLI overlaps a live GUI (and its scope discipline), item 3's played-at *value* source (metadata unit) and the honesty of the parse-cache key.

## Items in scope

1. **Keyboard shortcut reference** — a documented shortcut table; exists in the demo viewer today, extend app-wide
2. **CLI / flag-driven scripting** — CLI path argument / "Open with" and all-flags runs; CLI yes, TUI no — scope is a known concern (a CLI that can't do everything the GUI can would be a gargantuan effort)
3. **Parse cache and played-at ordering** — skip-reparse reparse plus library ordering by last-played time

## Current state

- **Shortcuts are documented per-surface, never centrally.** The one "shortcut table" is the Replay view's `KBD_HINTS` array (`src/frontend/src/lib/views/Replay.svelte` ~line 2763) — deliberately VIEW-LOCAL (comment says the shortcuts are this view's own; it rides the toolbar's keyboard-icon `title`, one per line) and pinned by `src/frontend/test/replay.dom.mjs` (exactly 10 lines, exact strings). The key *bindings* live in `src/frontend/src/lib/replay/input.js` (Space · `,`/`.` · `←`/`→` · `Shift+←/→` · `[`/`]` · `L` · `F` · `1-9,0` · `X` · `S`, plus its text-entry/range/control-target guard rules) with the map also written out in its header comment — i.e. the same table is duplicated twice today. Everywhere else shortcuts are scattered in footers/tooltips: CommandPalette `Ctrl/⌘K` + footer (`components/CommandPalette.svelte`, window-level keydown), SQL console `Ctrl/Cmd+Enter` (`views/SqlConsole.svelte`), picker footers `↑↓ move · Enter select · Esc close` (`MatchPicker`, `PlayerPicker`, `SuggestInput`, all three with the same footer string), and the canonical Escape/Enter behavior owned by `Dialog.svelte`/`Popover.svelte`/`ConfirmDialog.svelte`. Table/list rows use Enter-to-activate (`Library`, `Match`, `PlayerProfile`, `Profiles`, `LandmarkRow`, `StatCard`, `EconCurve`) — a11y affordances, arguably not "shortcuts". No help view, no `?` binding, no central registry, no global keymap dispatcher; `replay/audio.js`/`sfx.js` keydown listeners are autoplay-unlock, not shortcuts.
- **CLI: exactly one flag, one proven headless path.** `src/main.go` `flag.Parse()` → `spectra -import <path>` → `runImport()`: `data.EnsureDirs` + `store.Open` + prefs kvstore + `library.New{Parse, ParserVersion, CopyEnabled}` (Emit left nil — `emitEvent` is nil-safe) + `Enqueue` + poll `ListJobs`. Everything the GUI wires (`app` + 15 services) is registered *after* that early return; services take `app` mostly for `spectra:*` events, so the store/importer/report/query layers are app-free by construction. Positional args are ignored (`flag.Args()` unused); there is no `-version`/subcommand structure. **No file association:** `src/build/linux/spectra.desktop` is `Exec=spectra` with no `MimeType`; NSIS/MSIX packaging has no `.dem` association either. **No single-instance plumbing** in the app — but Wails v3 ships it (`application.SingleInstanceOptions{UniqueID, OnSecondInstanceLaunch, ExitCode}`, verified in the pinned module) and it is simply not configured. Drag-and-drop argv-equivalent already exists: `EnableFileDrop` → `spectra:files-dropped` → frontend `importPaths`.
- **Export/query headless surface:** report rendering is pure Go (`internal/report` embedded templates + `renderReportDoc` in `platformservice.go`), SQL is pure Go (`internal/query.Session.Run` over the `mode=ro`+`query_only` connection), `store.ListMatches*` are plain queries. **CSV is NOT:** `frontend/src/lib/csv.js` is the one CSV serializer (SqlConsole/landmark export) and no `encoding/csv` usage exists anywhere in Go — any CLI CSV output of frontend-shaped tables would be a port.
- **Parse cache:** none. `matches.sha256` is `UNIQUE` and `process()` rejects a re-import with "already imported (match N)" *after* hashing — so re-import of unchanged bytes already costs only a hash. `Reprocess` (Library "Re-parse" button) always re-parses: resolve file → claim → hash → `extract.Parse` → `SaveExtracted` → analytics; the only skips today are cancel/stopping pre-claim paths. `matches.parser_version` is stamped per match from `extract.ParserVersion` (const = the demoinfocs library version) and shown in Settings/Match/Explorer; it is *not* bumped when Spectra's own extraction logic changes. `RecomputeAnalysis` already skips the parse entirely (analytics-only refresh).
- **Ordering:** `store.matchListSort` whitelist (default `extract_at`), `ListMatches`/`ListMatchesPage` (keyset, NULL-safe tie-break arms already generic), frontend `Library.svelte` `SortTh` set (Map/Score/Rounds/Duration/Size/**Imported**/Status) with `extracted_at` default. **No `played_at`/`last_opened` column exists** (grep: zero hits) and no index exists on `extracted_at` (the Tier-1 block in `schema.sql` indexes steam_id/kind/jobs only — `matches` is sorted as a whole table, cheap at library scale).

## Implementation path

### 1. Keyboard shortcut reference — LoE: S
- **Inventory first (cheap, done):** global = `Ctrl/⌘K` palette (only true app-wide hotkey); Replay = the 10 `input.js` transport keys (active only while the Replay view is mounted, window-level); SQL console = `Ctrl/⌘Enter`; pickers/suggests = `↑↓/Enter/Esc` footers; dialogs/popovers = `Esc`/backdrop (canonical in `Dialog`/`Popover`/`ConfirmDialog`); list-row `Enter` = a11y, list in the table but mark as such.
- **Path = a documented table, NOT a keymap dispatch rewrite.** New canonical home `frontend/src/lib/shortcuts.js`: one exported grouped array (Global · Replay · Lists & pickers · Dialogs · SQL console), each entry `{ keys, action, scope }`, with the strings sourced from the existing `input.js` header/`KBD_HINTS` wording so no user-visible text changes. A reference surface then consumes it: a "Keyboard shortcuts" entry in the CommandPalette (`nav.js`/palette Actions section) opening a `Dialog` table — VS Code design language, zero new chrome; an optional `?` binding (guarded by the same text-entry rules as `input.js`) is a follow-through, not v1.
- **Drift policy:** v1 documents rather than enforces — keep `KBD_HINTS` view-local (its comment argues for it) and add a pin test asserting it equals the registry's Replay slice, OR migrate `KBD_HINTS` to source from the registry and update `replay.dom.mjs`'s exact-string pin in the same change. Do **not** build a central dispatcher that routes keys through the registry — that would touch `input.js`'s carefully-guarded handler and the palette for no user value (that refactor is L territory and belongs with any future keybinding-remapping feature, which is not on the roadmap).
- Convention hook: AGENTS canonical-homes table gets a row (`lib/shortcuts.js` — THE shortcut table) so future units (annotations' "notes with keyboard shortcuts", replay additions) extend it instead of inventing footers.

### 2. CLI / flag-driven scripting — LoE: M (scoped v1; unscoped parity = L+, out of scope by the owner's own concern)
- **Scoped v1 = flags over services that are already app-free**, all in `main.go` beside `runImport`, mirroring its composition (EnsureDirs → store.Open → kvs → service):
  - positional path args (`spectra a.dem b.dem.zst`) → GUI launch + import kickoff (reuses the `spectra:files-dropped` → `importPaths` frontend path, or calls `Enqueue` directly before `app.Run`);
  - `-import` (exists — keep behavior byte-identical, dev smoke tests depend on it);
  - `-list [--json|--csv]` → `store.ListMatches` (canonical sort whitelist) to stdout;
  - `-query "SQL" [--csv|--json]` → `internal/query.Session.Run` (the same ro/timeout/row-cap guard) — CSV here means a tiny Go cell writer for *query result rows only*, not a port of `lib/csv.js`;
  - `-report <id|all> [--template] [--out dir]` → `renderReportDoc` (pure Go, embedded templates);
  - optional `-reprocess <id>`.
  - **Explicitly deferred (name in docs):** whole-match 34-table CSV export, landmark/position export, YAML metric runs, anything whose row-building lives in the frontend. This is the scope answer to the owner's gargantuan concern: v1 covers "import + read + report" scripting, not GUI parity; each later flag rides the same `runX` pattern when its Go service exists.
- **"Open with" plumbing:** (a) argv positional handling above; (b) file association — add `MimeType=application/x-dem;application/x-dem-zst` (or `application/octet-stream` suffix rules) to `build/linux/spectra.desktop` + `.dem`/`.dem.zst` association in NSIS (`project.nsi`) and MSIX; (c) **single instance**: configure Wails `SingleInstanceOptions` on the GUI branch so a second launch forwards its argv via `OnSecondInstanceLaunch` → first instance imports and focuses — otherwise "Open with" spawns a second process against the same single-writer DB (see risks). Headless flag runs (`-import` etc.) must bypass single-instance and still execute (decide the ordering in `flag.Parse` before `application.New`).
- **Structural hard parts (name, don't solve here):** (1) `store.Open` unconditionally fails *other* instances' queued/running jobs ("interrupted by restart") — CLI runs against a GUI-held library are unsafe today; needs a policy (GUI holds the write DB; CLI query/list either opens a read-only variant or refuses when the GUI is live). (2) Frontend-owned logic (CSV semantics, native save dialogs, Builder/YAML authoring) is not CLI-reachable without ports — defer by scoping. (3) Headless progress = `runImport`'s poll loop; more flags want a small shared "job → stderr progress" helper rather than N copies.

### 3. Parse cache and played-at ordering — LoE: S (creeps to M if the skip predicate/semantics need owner debate)
- **Skip-reparse (reprocess fast-path):** in `internal/library`'s worker, before the parse stage of `jobKindReprocess`: if the match row is ready **and** `matches.parser_version == extract.ParserVersion` **and** the expected sidecars are present (at minimum: position sidecar when `position_frames > 0` — Replay's own hint tells users Re-parse is how you *gain* position data, so completeness is the predicate, not just the stamp) → complete the job immediately (job done, `EventJobDone`/`EventLibraryChanged` emitted as today, no parse). Key = existing columns (`sha256` + `parser_version`), no new state, no version ladder — consistent with the pre-release no-versioning policy. Import-time dedupe already short-circuits unchanged *re-imports*; this covers the Re-parse button and any future automatic reparse. Ship a force path (the UI's Re-parse intent when data is incomplete must never be skipped) and a characterization test pinning "skip only when complete + stamp matches".
- **Played-at ordering:** one new nullable `played_at DATETIME` on `matches` (baseline schema — remember `CREATE … IF NOT EXISTS` won't alter existing dev DBs; per policy they're wiped/re-imported, no migration) + `matchListSort["played_at"]` + `matchCols` extension (auto-pinned by `TestColumnListConstsMatchSchema`) + a `SortTh` "Played" header in `Library.svelte` (keep `extracted_at`/"Imported" as-is; other pickers stay on `extracted_at`). Keyset pagination's NULL arms already give correct placement for undetected rows. Index: **none at first** — there's no `extracted_at` index either and `matches` sorts as a whole table; add one in the Tier-1 block (pattern pinned by `indexes_test.go`) only if measured slow. Value source is the metadata unit's played-at detection (see overlaps) — ordering ships with NULLs and fills in; the alternative reading (Spectra-side "last opened/watched" stamp written when the Replay view opens) needs a new write path and an owner decision, see risks.

## Existing scaffolding to reuse

- `main.go runImport` — the headless composition template (EnsureDirs → store.Open → kvs → `library.New` → poll); `Importer.emitEvent` nil-safety makes every importer call headless-safe.
- Go-owned services/layers: `store.ListMatches*` (sort whitelist + keyset), `internal/query.Session` (ro/timeout/row-cap), `internal/report` templates + `renderReportDoc`, `AnalyticsService.RecomputeAnalysis` (parse-free refresh precedent), `library.Importer.Reprocess` (the hook point for the fast-path).
- Frontend: `KBD_HINTS` + `input.js` header (wording to reuse verbatim), `CommandPalette` footer/Actions pattern (the reference's delivery vehicle), canonical `Dialog`/`Popover` for the table UI, `MatchPicker`-style footers (the scattered hints the registry consolidates), `services.js cachedRead`/`importPaths` for the argv→import hand-off, `SortTh` for the new sort header.
- Framework: Wails `SingleInstanceOptions` (second-launch argv forwarding) — no third-party dep.
- Tests to lean on: `replay.dom.mjs` shortcut pin, `TestColumnListConstsMatchSchema`/`indexes_test.go` (schema ripple), `TestOpenMarksStaleJobsInterrupted` (the multi-process hazard, already pinned as deliberate), queue/dedupe tests in `internal/library` (characterization base for the skip).

## Dependencies & overlaps

- **Metadata unit (owner of played-at *detection*):** this unit owns only the ordering plumbing; the value comes from their demo-source/played-at extraction. Sequencing is safe either way (NULL-tolerant), but only one unit may write the column. Clarify "last-played" semantics with the owner: demo's in-game date (metadata) vs. user's last-opened-in-Spectra (new write path here) — the roadmap phrase "last-played time" reads like the former.
- **Library unit:** `Reprocess`/queue lifecycle/`Enqueue` dedupe are its canonical homes — the skip must live inside the existing worker claim path, not beside it, and must not change cancel/coalesce semantics.
- **Export-formats unit (34 CSV tables / JSON / CSDM):** CLI export flags should ride *their* Go-side row builders when they exist; do not build a second CSV pipeline in `main.go` (only query-result cells get a local writer). Coordinate so `-report`/`-query` v1 doesn't pre-empt their format decisions.
- **YAML metrics / statistics units:** future `-metrics`/eval flags ride `MetricsService`/`internal/metrics` — defer; nothing to de-conflict now.
- **Replay unit:** owns `input.js` — the registry's Replay slice must be updated when it adds keys (AGENTS convention row makes this explicit). **Annotations unit** ("notes with keyboard shortcuts") will add more — same hook.
- **Localization:** all registry strings are English v1; one central table is exactly what localization later needs (no footer-by-footer sweep).
- **Release/packaging pipeline:** desktop-file/NSIS/MSIX association edits touch `build/` (lint-excluded, regenerated) and the release skill's asset contract — coordinate a packaging change, it is not code-only.
- **Dev workflow (AGENTS instance isolation):** enabling single-instance changes parallel-agent GUI-smoke behavior — see risks.

## Risks & unknowns

- **Item 2 — the DB is single-writer and `store.Open` repairs on every open:** any concurrent CLI + GUI run currently fails the GUI's in-flight jobs (`TestOpenMarksStaleJobsInterrupted` pins this as deliberate). "Open with" *requires* single-instance forwarding; plain `spectra -import` batching against a live GUI remains unsafe until a lock/read-only-open policy exists. This is the top blocker-class unknown for the item.
- **Item 2 — single-instance vs. parallel dev instances:** AGENTS documents coexisting per-worktree instances (kill-by-PID smoke runs) as normal; a fixed `UniqueID` would let one agent's launch hijack another's. The UniqueID likely must vary with the XDG instance dirs (or stay off for dev builds) — a real design decision, not a flag.
- **Item 2 — scope creep** (the owner's stated concern): every flag added beyond v1's import/list/query/report list re-opens "why can't it do what the GUI does". Freeze v1's flag list in the roadmap/README text and require each new flag to name its Go service.
- **Item 1 — truthfulness without enforcement:** a documented table drifts from handlers unless something pins it; the cheap pins (registry ↔ `KBD_HINTS`, footer strings) cover the loud surfaces only. Accept documentation-first drift risk rather than a dispatch rewrite (L).
- **Item 3 — cache-key honesty:** `extract.ParserVersion` tracks the demoinfocs *library*, not Spectra's extraction/analytics logic — extraction changes don't bump it, so a skip keyed only on it can serve stale rows after an app change (violating determinism's spirit). Mitigation: bump the stamp as part of the same discipline as golden-fixture regen, or restrict the skip to "sidecars complete + stamp match" and keep Re-parse's force path obvious. Owner should confirm what Re-parse is *for* (fix tool vs. re-run) before the skip lands — if it's purely a fix tool, the skip's trigger set may be thinner than expected and the item shrinks.
- **Item 3 — played-at ambiguity** (demo date vs. last-opened) and detection ownership (metadata unit); plus the standing schema policy: a new column never reaches existing DBs (reimport, no migration) — fine pre-1.0, but it means the ordering ships NULL-padded until metadata lands.
